# MathScribe

Handwritten and printed math → LaTeX, with a fine-tuned vision-language model
(Qwen3.5-4B + LoRA, trained with [Unsloth](https://github.com/unslothai/unsloth)).

> **Status: Phase 1 (evaluation harness).** The repo has a reproducible SFT command
> and an eval command. It has **no evaluated results yet**. See [PLAN.md](PLAN.md) for the roadmap.

## Results

There are no verified quality numbers yet. Every number about this project
comes from a script in this repo, and lives in [`reports/`](reports/):

- [`reports/leaderboard.md`](reports/leaderboard.md): generated by `run_eval`
  from the result files in [`reports/results/`](reports/results/).
- [`reports/phase0_reference.md`](reports/phase0_reference.md): the reference
  smoke run from the original notebook (training cost only, no quality metrics).
- The ablations (Phase 2) come later.

## Quickstart

### Local (code, tests, no training)

```bash
bash scripts/setup_env.sh          # uv venv + dev tools + pre-commit hooks
uv run pytest
uv run python -m mathscribe.train.sft --config configs/train/sft_smoke.yaml --dry-run
```

### Training (Colab or any CUDA GPU with ≥ 16 GB)

Open [`notebooks/colab_runner.ipynb`](notebooks/colab_runner.ipynb) in Colab, set
`HUB_REPO`, and run all cells. The notebook runs this command:

```bash
python -m mathscribe.train.sft --config configs/train/sft_smoke.yaml \
  --set hub.push=true --set hub.repo_id=<hf-user>/mathscribe-sft-smoke
```

On a machine with the train extra installed (`bash scripts/setup_env.sh --train`),
use `uv run python -m mathscribe.train.sft ...` instead.

### Checkpoints and resume

- The trainer saves a checkpoint every `train.save_steps` steps.
- With `hub.push=true`, each checkpoint also goes to the Hub repo, in `last-checkpoint/`.
- Add `--resume` to continue a stopped run. The script picks the most advanced
  checkpoint from the local `output_dir` and the Hub.
- Do not change `max_steps` or the batch settings when you resume. The schedule
  in the checkpoint depends on them.

Override any config value with `--set section.key=value` (for example
`--set train.max_steps=30`).

## Evaluation

The test set is a frozen, seeded subset of the `unsloth/LaTeX_OCR` `test` split:
1000 rows, seed 2026, pinned to a dataset revision. The manifest
[`data/testsets/latex_ocr_test.json`](data/testsets/latex_ocr_test.json) stores the
row indices and a hash of each row. The eval checks each row against its hash.
The rows are in random order, so `--subset N` (the first N rows) is also a random sample.

```bash
# Zero-shot base model (GPU). Use --subset for a fast check.
python -m mathscribe.eval.run_eval --config configs/eval/qwen35_4b_zeroshot.yaml --subset 100

# A fine-tuned adapter (Hub repo or local folder).
python -m mathscribe.eval.run_eval --config configs/eval/sft_smoke.yaml \
  --set model.name=<hf-user>/mathscribe-sft-smoke

# Score the stored raw outputs of a run again, with no GPU (after a metric change).
python -m mathscribe.eval.run_eval --config configs/eval/qwen35_4b_zeroshot.yaml \
  --set model.backend=jsonl \
  --set model.name=outputs/eval/qwen35_4b_zeroshot/latex_ocr_test_n1000/predictions.jsonl
```

On Colab, set `TASK = "eval"` in [`notebooks/colab_runner.ipynb`](notebooks/colab_runner.ipynb).
The last cell downloads the result JSON. Put it in `reports/results/`, then run
`python -m mathscribe.eval.leaderboard` and commit both files.

Every model gets the training prompt (text, then image) and greedy decoding.
`enable_thinking: false` makes the prompt end with `<think>\n\n</think>\n\n`, as in
the training target. The same `extract_latex` rules (code fences, `$…$` wrappers)
apply to every model. The metric definitions are in
[`src/mathscribe/eval/metrics.py`](src/mathscribe/eval/metrics.py).

The leaderboard shows a 95% bootstrap confidence interval for normalized match and CER.
It also shows each run's normalized match minus the zero-shot baseline, on the same rows
(a paired interval, [`bootstrap.py`](src/mathscribe/eval/bootstrap.py)). A `*` marks a
difference that is significant at the 5% level.
