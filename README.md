# MathScribe

Handwritten and printed math → LaTeX, with a fine-tuned vision-language model
(Qwen3.5-4B + LoRA, trained with [Unsloth](https://github.com/unslothai/unsloth)).

> **Status: Phase 1 done (evaluation harness and baselines).** The repo has a reproducible
> SFT command and one eval command for every model and baseline. The first results are in
> [`reports/leaderboard.md`](reports/leaderboard.md). See [PLAN.md](PLAN.md) for the roadmap.

## Results

There are no verified quality numbers yet. Every number about this project
comes from a script in this repo, and lives in [`reports/`](reports/):

- [`reports/leaderboard.md`](reports/leaderboard.md): generated by `run_eval`
  from the result files in [`reports/results/`](reports/results/).
- [`reports/data_splits.md`](reports/data_splits.md): the frozen test, val and CROHME sets,
  and their overlap with the training rows.
- [`reports/phase0_reference.md`](reports/phase0_reference.md): the reference
  smoke run from the original notebook (training cost only, no quality metrics).
- The ablations (Phase 2) come later.

## Quickstart

### Local (code, tests, no training)

```bash
bash scripts/setup_env.sh          # uv venv + dev tools + pre-commit hooks + renderer (node >= 18)
uv run pytest
uv run python -m mathscribe.train.sft --config configs/train/sft_smoke.yaml --dry-run
```

### Training (Colab or any CUDA GPU with ≥ 16 GB)

Open [`notebooks/colab_runner.ipynb`](notebooks/colab_runner.ipynb) in Colab, set
`HUB_REPO`, and run all cells. The notebook runs this command:

```bash
python -m mathscribe.train.sft --config configs/train/sft_smoke.yaml \
  --set hub.push=true --set hub.repo_id=<hf-user>/mathscribe-sft-smoke
```

On a machine with the train extra installed (`bash scripts/setup_env.sh --train`),
use `uv run python -m mathscribe.train.sft ...` instead.

### Checkpoints and resume

- The trainer saves a checkpoint every `train.save_steps` steps.
- With `hub.push=true`, each checkpoint also goes to the Hub repo, in `last-checkpoint/`.
- Add `--resume` to continue a stopped run. The script picks the most advanced
  checkpoint from the local `output_dir` and the Hub.
- Do not change `max_steps` or the batch settings when you resume. The schedule
  in the checkpoint depends on them.

Override any config value with `--set section.key=value` (for example
`--set train.max_steps=30`).

## Evaluation

### Test sets

Three frozen manifests in [`data/testsets/`](data/testsets/). Each stores the dataset
revision, the seed, the row indices, and a hash of each row. The eval checks each row
against its hash. Details and the overlap with the training rows are in
[`reports/data_splits.md`](reports/data_splits.md).

| Set | Rows | Use |
|---|---|---|
| `latex_ocr_test.json` | 1000 of the `unsloth/LaTeX_OCR` `test` split | printed test set (default) |
| `crohme2014.json` | all 986 rows of CROHME 2014 | handwritten test set |
| `latex_ocr_val.json` | 1000 of the `train` split | validation; training excludes it with `data.exclude` |

The rows are in random order, so `--subset N` (the first N rows) is also a random sample.

### Metrics

- Text: exact match, normalized match, CER, BLEU ([`metrics.py`](src/mathscribe/eval/metrics.py)).
- Render: compile rate and render match ([`render.py`](src/mathscribe/eval/render.py)). The
  renderer (MathJax + resvg in node) renders the prediction and the reference. Render match
  compares the two images column by column, without the empty columns, so spacing does not count.
- The leaderboard shows 95% bootstrap intervals, and the difference to the zero-shot
  baseline on the same rows (paired, [`bootstrap.py`](src/mathscribe/eval/bootstrap.py)).
  A `*` marks a difference that is significant at the 5% level.

### Commands

```bash
# Zero-shot base model (GPU). Use --subset for a fast check.
python -m mathscribe.eval.run_eval --config configs/eval/qwen35_4b_zeroshot.yaml --subset 100

# A fine-tuned adapter (Hub repo or local folder).
python -m mathscribe.eval.run_eval --config configs/eval/sft_smoke.yaml \
  --set model.name=<hf-user>/mathscribe-sft-smoke

# The same model on the handwritten test set.
python -m mathscribe.eval.run_eval --config configs/eval/qwen35_4b_zeroshot.yaml \
  --set testset.manifest=data/testsets/crohme2014.json

# Score the stored raw outputs of a run again, with no GPU (after a metric change).
python -m mathscribe.eval.run_eval --config configs/eval/qwen35_4b_zeroshot.yaml \
  --set model.backend=jsonl \
  --set model.name=outputs/eval/qwen35_4b_zeroshot/latex_ocr_test_n1000/predictions.jsonl
```

### Baselines

| Config | Model | Where | Setup |
|---|---|---|---|
| `qwen35_4b_zeroshot.yaml` | Qwen3.5-4B, zero-shot | Colab | `--colab` (runner notebook) |
| `qwen35_9b_zeroshot.yaml` | Qwen3.5-9B, zero-shot, 4-bit | Colab | `--colab` (runner notebook) |
| `claude_opus55.yaml` | Claude Opus 5.5 through the API | local, no GPU | `bash scripts/setup_env.sh --api` + an Anthropic credential |
| `pix2tex.yaml` | pix2tex 0.1.4 | local GPU | `bash scripts/setup_env.sh --baselines` |
| `got_ocr2.yaml` | GOT-OCR 2.0 (format mode) | local GPU | `bash scripts/setup_env.sh --baselines` |

On Colab, set `TASK = "eval"` in [`notebooks/colab_runner.ipynb`](notebooks/colab_runner.ipynb),
and list the models in `EVAL_RUNS` and the test sets in `EVAL_TESTSETS`. The notebook runs each
model on each test set, and the last cell downloads `eval_results.zip`. In your local clone:

```bash
unzip -o eval_results.zip      # reports/results/*.json and outputs/eval/*/predictions.jsonl
uv run python -m mathscribe.eval.leaderboard
```

Every Qwen model gets the training prompt (text, then image) and greedy decoding.
`enable_thinking: false` makes the prompt end with `<think>\n\n</think>\n\n`, as in
the training target. The same `extract_latex` rules (code fences, `$…$` wrappers)
apply to every model. The Claude baseline also gets a system prompt that asks for the
LaTeX only (see its config).
